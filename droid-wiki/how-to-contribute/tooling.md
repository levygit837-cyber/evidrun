# Tooling

Evidrun's tooling is substantial because the contracts drive generated artifacts and the docs are a checked artifact. This page documents the build commands, generators, linters, migrations, and how they fit together.

## Package managers

- **Python:** `uv` with the `evidrun` package built by hatchling from `src/evidrun` (`pyproject.toml`). `uv sync --extra dev` installs runtime deps plus the dev tools. The `package` extra adds `pyinstaller` for the desktop backend binary.
- **Node:** pnpm 9.15.0 workspace, packages under `apps/*` (`pnpm-workspace.yaml`). `pnpm install` sets up the web and desktop apps.

## Python console scripts

`pyproject.toml` declares three entry points:

| Script | Target | Purpose |
| --- | --- | --- |
| `evidrun` | `evidrun.entrypoints.cli.app:main` | The Typer CLI (init, doctor, demo, serve, contract, study, run, bundle, provider, authority, data). |
| `evidrun-api` | `evidrun.entrypoints.api.app:run` | Runs the FastAPI app with uvicorn on `EVIDRUN_PORT` (default 8765). |
| `evidrun-worker` | `evidrun.entrypoints.worker.app:main` | The local worker entry point. |

## The generators

Contracts are frozen Pydantic models; schemas and TypeScript types are generated from them, never hand-written.

### `scripts/generate_schemas.py`

Reads the contract models from `evidrun.contracts` and emits, into `schemas/generated/`:

- one JSON Schema per contract into `contracts/<name>.json` (21 models, from `CONTRACT_MODELS`),
- `contracts/catalog-v1.json`, a discriminated union of every contract (the input for the TS generator),
- `contracts/run-event-payload-catalog-v1.json`,
- `experiment-manifest-v1.json` for the legacy manifest,
- `openapi-v1.json`, generated by building the FastAPI app and calling `app.openapi()`.

With `--check` it renders the same content and compares against what is committed, raising `SystemExit` and listing stale paths instead of writing. CI runs `generate_schemas.py --check` in the Python job.

### `scripts/generate_contract_types.mjs`

Compiles `schemas/generated/contracts/catalog-v1.json` into `apps/web/src/generated/contracts.ts` using `json-schema-to-typescript`, with a fixed banner (`Do not edit by hand`) and formatting. With `--check` it reads the current file and throws if it differs. CI runs this in the Node job.

The rule: after changing a contract model, run `pnpm generate:contracts` and commit both the regenerated JSON Schemas and `contracts.ts`. See [patterns and conventions](patterns-and-conventions.md) and [reference: data models](../reference/data-models.md).

### `scripts/validate_docs.py`

Validates the YAML frontmatter of every `docs/**/*.md`, requiring the full key set (`id`, `type`, `title`, `status`, `authority`, `owner`, `created_at`, `updated_at`, `applies_to`, `sources`, `supersedes`, `superseded_by`, `implementation_refs`, `verification_refs`). It rejects unknown statuses, duplicate IDs, `implemented` without `implementation_refs`, `verified` without `verification_refs`, and references to paths that do not exist. On success it writes `docs/_generated/manifest.json`. CI runs the validator and then `git diff --exit-code -- docs/_generated`, so a stale manifest fails even when the validator passes.

### `scripts/smoke_desktop_handshake.mjs`

Spawns `evidrun serve --desktop-handshake`, sends `{ token, data_dir, parent_instance_id }` on stdin, reads the readiness JSON, and asserts that `/api/v1/health` is 401 without the bearer token and 200 with it. Run via `pnpm test:handshake`. It is a manual/optional check, not part of `pnpm test`.

## Linting and type checking

- **ruff** (`[tool.ruff]`): target `py314`, line length 100, lint rule sets `E, F, I, UP, B, SIM, RUF`, first-party `evidrun`. Run `uv run ruff check .`.
- **pyright** (`[tool.pyright]`): `pythonVersion` 3.14, `typeCheckingMode = "strict"`, includes `src`, excludes `.venv`, `reportUnusedFunction = false`. Run `uv run pyright`.
- **TypeScript**: strict; `typecheck:web` and `typecheck:desktop` run `tsc --noEmit` against the respective tsconfigs.

## Database migrations

Alembic manages the schema. `alembic.ini` points at `sqlite+pysqlite:///evidrun.db` and prepends the repo root to `sys.path`. `alembic/env.py` binds `target_metadata` to `Base.metadata` from `evidrun.infrastructure.database.models`, so autogenerate sees the SQLAlchemy models. Migrations live in `alembic/versions/` (`0001_contract_foundation.py`, `0003_human_authority.py`). `tests/integration/test_contract_migration.py` runs a migration against the models. At runtime, `Database.create_all()` also creates tables directly for the local store. See [reference: data models](../reference/data-models.md) and [systems: database](../systems/database.md).

## CI

`.github/workflows/ci.yml` has a `python` job (ruff, pyright, pytest, docs validator, schema check, manifest diff) and a `node` job (contract-type check, typechecks, web/desktop Vitest, build). See [development workflow](development-workflow.md) for the full mapping.
